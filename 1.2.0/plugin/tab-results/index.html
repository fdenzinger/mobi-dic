    Google Earth QGIS Results

    Results¶

    The Results tab is the starting point for inspecting DIC outputs inside QGIS. After a processing run has completed, point it to the output directory and scan for results. You can then select individual displacement components, configure their colour scale and range, and load them directly into the QGIS layer tree with one click. From the same tab you can also export layers to Google Earth Pro as georeferenced KMZ overlays, optionally with time slider support for multi-date datasets.

    The workflow is straightforward:

    1. Check the Directory (filled in from the Processing output folder). The folder is scanned automatically.
    2. Tick the components you need and click ▶ Load Selected into QGIS.
    3. Optionally click 🌍 Export to Google Earth Pro… to create KMZ files from the scanned layers.

    The tab has three collapsible sections: Select layers (open by default), Appearance and Google Earth export. The Appearance header shows the current state, for example "default colour scales · opacity 80 %".

    Select layers¶

    Discover and select the displacement layers to load. Point the plugin to the output directory, trigger a scan, and choose which components to bring into QGIS.

    Directory & scan¶

    Directory is the root folder of a DIC processing run. It is filled in automatically from the Processing output folder and scanned without pressing anything. The scan searches recursively for all DIC_*.tif files and populates the layer list; range computation for the Symbology table is triggered at the same time.

    When does the automatic scan run?

    Only when the directory has changed since the last scan and the Results tab is visible (shortly after you stop typing a path, or when you open the tab). Switching between tabs does not re-scan an unchanged folder, and a very large output folder (e.g. a SWISSIMAGE tile batch) is never scanned in the background. Use ↻ Rescan to scan again, for example after a new run has finished.

    Data type¶

    Choose Displacement results (default) or Velocity results, the same choice as in Map Layout. Displacement shows the cumulative displacement layers, the sparse GeoPackages and the input images. Velocity shows only the _vel_ layers (written when Export velocity is enabled). Switching only re-filters the files already scanned, so no new scan is needed. Sparse GeoPackages written with Export velocity on also contain velocity columns (x_vel_<unit>, y_vel_<unit>, xy_vel_<unit>, and in DEM mode z_vel_, dz_vel_, xyz_vel_, e.g. xy_vel_myear; displacement divided by the time between the two dates, like the velocity GeoTIFFs). They are listed under Velocity results (Sparse GPKGs in the filter) and can be loaded as coloured points or arrows coloured by the chosen velocity component; arrow direction is unchanged. GeoPackages from earlier runs have no velocity columns and stay under Displacement results. When files of the other type exist, the status line tells you how many are hidden.

    Input images as layers¶

    Switch on the Primary / Secondary buttons in the layer grid (column Primary / secondary image) to add the two input files from the Input / Output tab to the result group when you load layers. They are placed below all results with QGIS' default rendering; the primary image is switched on, the secondary one is added switched off in the layer tree (tick it to compare the epochs). In DEM mode Draw DEMs as hillshade (default on) shows the input DEMs as a multidirectional hillshade (azimuth 315°, elevation 45°, assumes a metric CRS) instead of grey elevation values. The buttons only appear once the input files are set in Input / Output. In Camera mode the images appear in pixel coordinates, in the same place as the results (the plugin writes camera results with the same pixel convention as QGIS uses for an image without georeferencing; results written from the command line with rescale_results: false use a different vertical origin and would be offset).

    Choosing layers¶

    There is no separate filter: the layer grid (see below) is the selection. Switch single layers, whole columns (a component for all pairs) or whole rows (one pair) on or off. The Appearance section follows the selection: the colormap table is shown for the ticked raster components and for the component of ticked sparse points (rows marked points, with the default colormap of the matching raster component), and the point and arrow settings appear when a sparse-points column is ticked. Rows set to Auto also recompute their colour range from the ticked rasters only (a moment after each change); ranges you have edited by hand are not touched.

    Sparse GeoPackage layers¶

    Whenever sparse GeoPackages are found (sparse, coherence-filtered or neighbour-filtered), a Sparse points, component dropdown appears above the grid. It defaults to xyz (3D magnitude) in DEM mode and xy (2D magnitude) in Ortho and Camera mode; choose all or another component if you need it. Your choice is kept while you stay on the same GeoPackage type.

    Arrow layers are always loaded fully opaque (100 %, arrow colours without transparency); the layer opacity setting applies to the rasters and the coloured points.

    Coloured points are styled in the colour table of Appearance, in the rows marked points (for example XY points), which appear for the component of the ticked sparse points. Per row: Colormap: the default is the colour family of the raster of the same component (RdBu for X, Y, Z, dZ; Deformation (QML) for XY, XYZ; Twilight for AZ; RdYlBu_r for DIP); choose RdBu, Deformation (QML), AZ / Twilight, DIP / RdYlBu_r, YlOrRd or Viridis to change it. Range: Min–max (default, the extremes of the loaded field), Percentile (the low / high percentile set in Settings → Results, default 5–95 %, robust against a few outliers; computed once per layer) or Fixed (the default Min and Max of the component from Settings → Results) or Custom with your own Min and Max (editable only in this mode; points outside the range are not drawn). For signed components such as X, Y, Z, dZ and DIP the first two modes make the range symmetric around zero so zero keeps the neutral colour; azimuth keeps 0–360°. With the component all, every loaded component has its own row. Point size (circle diameter in mm, default 1.5) stays in the vector display options. Changes apply live to point layers that are already loaded.

    Arrows always show the horizontal displacement

    Arrow direction and length come from the x and y fields, also in DEM mode; a map arrow cannot show the vertical part. The Component you choose (e.g. xyz, z) only sets the colour of Magnitude arrows and the field that Max magnitude and Hide arrows above test. With xyz an arrow can therefore look short but be coloured as a large displacement when the movement is mostly vertical. Choose xy if arrow length, colour and cut-off should describe the same horizontal displacement. The direction filter uses the horizontal direction only.

    Vector display (shown for GeoPackage layers) selects Coloured points, Black arrows or Magnitude arrows. For Magnitude arrows you can set the Max magnitude (top of the colour scale) and the Colormap: Green – Yellow – Red (default), Deformation scale (same colours as the XY/XYZ rasters), YlOrRd, RdYlBu_r or Viridis. With Auto size and density (default, recommended) the arrows are made readable automatically: the DIC grid is thinned so that about Arrows across map arrows (default 40) span the longer side of the data, keeping every k-th point in x and y (the value is limited to what the grid holds, i.e. every point; a grey note next to it shows the resulting thinning, the approximate number of arrows and that maximum once a layer is loaded; 20–80 is readable, much higher values turn the arrows into blobs and make QGIS slow); the arrow length is scaled (in map units, so it follows the map scale) so that a typical (upper-quartile) arrow is one thinned grid spacing long; and the arrowhead and line widths follow that length (multiplied by Thickness). The data is not changed, points are only hidden by the layer's renderer, which also makes large layers much faster to draw. Untick it to set scale and widths manually.

    Live adjustment. After arrow layers have been loaded, changing Arrows across map, Thickness, Max magnitude, Hide arrows above, Colormap or the manual scale and width fields restyles the loaded arrow layers shortly after the last change (about 0.3 s), without reloading. With the direction filter on, a new density re-thins the temporary copy from points that were read once at load time. Switching Auto size and density off or on is also live: when you untick it, the manual scale and width fields are filled with the sizes Auto was drawing at the current map scale (so the arrows do not jump) and then update the loaded layers as you change them; with the direction filter on, the arrows stay thinned at the last automatic density. Ticking the Direction filter also works on arrow layers that are already loaded: each loaded Auto arrow layer is replaced, at the same place in the layer tree and with the same name, visibility and opacity, by the temporary filter copy (the layer's internal id changes, so map themes or print layouts that reference the old layer by id would need to be updated; layers loaded with Auto off are skipped with a note). Unticking it shows all arrows again. Only the display type (Coloured points / Black arrows / Magnitude arrows) still requires a reload. The Max magnitude row also has the Hide arrows above checkbox next to the value; for Black arrows the value is greyed out until the box is ticked.

    Saving the result. Once the filters look right, 💾 Save filtered points… (in the arrow options) writes the points that pass them to a new GeoPackage: the direction-deviation threshold of the slider (if the direction filter is ticked) and, if ticked, the Hide arrows above cut-off on the magnitude field. The file contains all original attributes plus dir_dev and is written at the full DIC resolution: the deviation is computed for every point of the grid, not only for the thinned arrows on screen. The source GeoPackage is never changed. With several arrow layers loaded you pick a folder and get one file per layer (named <source>_filtered_dir<angle>_max<value>.gpkg). Writing hundreds of thousands of points can take a while.

    Remembered settings. The vector display settings (display type, Auto, arrows across map, thickness, direction filter and angle, Max magnitude and cut-off, colormaps, manual scale and widths, point size and the colormap and range of each points row) are stored between QGIS sessions and restored when the plugin opens.

    Direction filter (needs Auto): tick Direction filter: hide arrows that deviate from their neighbours before loading. The plugin then loads a thinned, temporary copy of the points that carries, for each arrow, the angle between its direction and the median direction of its 5 × 5 grid neighbours (component-wise median of the neighbours' unit vectors) (computed from all points of the DIC grid; points with fewer than 6 valid neighbours count as 180°). The Max deviation slider (5°–180°, 180° = show all) then hides arrows above the chosen angle immediately in all loaded arrow layers, and shows how many arrows remain. Use it to explore how much of the field is directionally inconsistent. Computing the deviation reads every point once, which can take a few seconds for very large layers. The copy is a scratch layer that QGIS does not save with the project: 📌 Keep filter layers in project writes each one to a GeoPackage next to its source (<source>_dirfilter.gpkg) and replaces the scratch layer by that file (same name, place, style and threshold), so it is still there when the project is reopened. The slider picks such layers up again when the Results tab is shown.

    Max magnitude is the top of the colour scale. By default arrows above it take the top colour (Magnitude arrows) or are all drawn (Black arrows). Auto next to Max magnitude sets it to the high percentile of the loaded field (rounded up), so a few outliers do not compress the colour scale. Tick Hide arrows above (next to Max magnitude, both arrow styles) to hide them instead; the data is not changed, arrows are only hidden by the layer's renderer (not applied to azimuth/dip fields). The colormap applies to the layers loaded into QGIS; Google Earth vector exports keep their own colour scale, but honour the cut-off.

    Layer list¶

    The found files are shown as a grid of toggle buttons: one block per run (its processing parameters as the title), one row per image pair and one column per layer type, in this order: Sparse points, GeoTIFF results, Primary / secondary image (the input files from Input / Output) and DIC input images (hillshade / gradient rasters). A blue button means the layer will be loaded; click it to switch it off. Clicking a column header switches that layer type on or off for all pairs, clicking a row label does the same for one pair; hover a button to see the file name. The grid is as tall as it needs to be and only scrolls when there is more than one time step. Tick Show file names to see the plain file list instead; it has the same order and also shows the Primary image and Secondary image entries (switched off by default), which are the same switches as the grid buttons.

    The Sparse points, component selector above the grid chooses which component the loaded sparse points are coloured by (all loads one layer per component).

    Click ▶ Load Selected into QGIS to load the blue layers. Use the quick-select buttons All, Sparse points, Magnitude only, DIC inputs (hillshade and gradient rasters) and None to manage the selection quickly. Layers are loaded into a named group in the QGIS layer tree (the group of an earlier load of the same folder is reused). New layers are always added on top of the group, and sparse point / arrow layers are always placed above the GeoTIFF layers.

    Output components¶

    Each DIC run produces one GeoTIFF per displacement component:

    Layer Modes Physical meaning
    DIC_x DEM, Ortho East–West displacement. Positive = eastward.
    DIC_y DEM, Ortho North–South displacement. Positive = northward.
    DIC_xy DEM, Ortho 2-D horizontal magnitude: \(\sqrt{x^2 + y^2}\). Always ≥ 0.
    DIC_dz DEM only Vertical displacement before co-registration offset is restored.
    DIC_z DEM only Vertical displacement after co-registration offset is restored — the physically meaningful value.
    DIC_xyz DEM only 3-D magnitude: \(\sqrt{x^2 + y^2 + z^2}\). Always ≥ 0.
    DIC_az all modes Displacement azimuth in degrees clockwise from North (0–360°); in Camera mode from the top of the image (0° = up, 90° = right).
    DIC_dip DEM only Displacement dip angle from horizontal (−90° to +90°). Positive = upward.
    DIC_ee DEM, Ortho Correlation error — normalised RMS residual from the DFT registration.

    Optional input images. If Export hillshades / Export gradient images was enabled, the run also contains DIC_input_hillshade_*, DIC_input_gradmag_* and DIC_input_gradang_* rasters (primary prim and secondary seco). They show what the correlation was run on — see Correlation input images for what each one means. They are listed first (in processing order). The component filter offers them as Hillshades, Gradient direction images and Gradient magnitude images (each shown only if present), plus Input images (all) when more than one kind exists; the Input images quick-select button ticks all of them, and are styled automatically: a grey stretch for hillshade and magnitude and the cyclic twilight scale (0–360°) for direction. Primary and secondary of the same kind share one grey range (union over all loaded files), so they are directly comparable.

    EE (correlation error): What it measures

    EE is the normalised RMS registration error from the DFT cross-correlation algorithm (Guizar-Sicairos et al. 2008):

    \[\mathrm{EE} = \sqrt{\left|1 - \frac{|\mathrm{CC}_\max|^2}{E_\text{ref} \cdot E_\text{sec}}\right|}\]

    where \(\mathrm{CC}_\max\) is the cross-correlation peak value and \(E_\text{ref}\), \(E_\text{sec}\) are the total spectral energies of the reference and secondary image windows. A value of 0 means a perfect correlation peak; 1 means no correlation at all.

    EE always reflects the quality of the 2-D image correlation — for Ortho and Camera mode this is the orthoimage patch; for DEM mode it is the hillshade or orientation image used as the correlation feature. It is therefore an XY-plane quality indicator in all modes and does not directly reflect the vertical displacement quality in DEM results.

    A more representative quality metric is planned for a future release.

    Appearance (symbology and display)¶

    Configure the colormap and colour range applied to each component before loading. Each component has sensible defaults but can be overridden per-component or globally with a custom QML file.

    Symbology table¶

    Each component row has four configurable columns:

    Column Description
    Colormap Named colour scale or a custom QML file
    Min / Max Values mapped to the two ends of the colour ramp
    Range Percentile (default) — Min/Max from the data of the ticked rasters without outliers (percentiles from Settings → Results); Min–max — the extremes of that data; Fixed — the default Min/Max of the component from Settings → Results; Custom — you enter Min and Max yourself (editing a value switches the row to Custom). Min and Max are greyed out in all modes except Custom, but show the values that will be used (they update when you change the ticked layers or the component)

    Default colormaps per component:

    Component Default colormap Notes
    X, Y, Z, dZ RdBu (diverging) Range centred at zero
    XY, XYZ Deformation QML Magnitude — always ≥ 0
    AZ AZ bundled QML Fixed 0–360°
    DIP DIP bundled QML Fixed −90° to +90°
    EE YlOrRd Fixed 0–1

    In Percentile and Min–max mode, symmetric components (X, Y, Z, dZ) are automatically centred at zero: bound = max(|low|, |high|), range set to [−bound, +bound]. AZ, DIP, and EE always keep their fixed defaults regardless of this setting.

    Use ↺ Reset ranges to Auto to switch all rows back to Percentile and recompute from data. In the colour table the rows for sparse points come first, then the raster rows.

    Layer names and groups¶

    By default (Layer names: Compact) loaded layers are organised by run instead of using the long file names:

    ▾ Borehole                                                               ← main group: run name
  ▾ RES 1 m · WIN 32 · SKF 4 · Orientation image · CoReg off · OS 10     ← processing parameters
      ▾ Points & arrows
          Arrows XYZ · 2022-10-14→2023-08-16 · 306 d
          Sparse XY · 2022-10-14→2023-08-16 · 306 d
      ▾ Results
          XY · 2022-10-14→2023-08-16 · 306 d
          X · …
      ▸ Input images
          Primary image · 2022-10-14
      ▸ DIC inputs
          Grad. mag. prim · 2022-10-14
▾ Brienz                                                                 ← another run, its own main group
  ▸ RES 0.5 m · WIN 64 · …
    • Main group = run name, group below = parameters. Data of different runs (different names) goes into separate main groups. Inside, one group per parameter set (resolution, window, skip factor, correlation feature, co-registration, oversampling) makes it clear with what the layers below were calculated; several parameter sets of the same run (a sweep) sit side by side under the run name. Groups are matched by the run name and the full run tag, not by their titles. Loading again adds to the existing groups.
    • Layer = component, time span and time difference (306 d); the run name is in the main group and is not repeated in every layer name. Input images show the date of their epoch. Velocity layers carry their unit (XY vel m/yr).
    • Sub-groups Points & arrows, Results, Input images (primary / secondary image) and DIC inputs (hillshade and gradient rasters) keep the fixed stacking order: sparse points on top, then the GeoTIFF results, the input images and last the DIC inputs. When a load contains several pairs of the same run (a time series), each pair gets its own sub-group named date1→date2 · n d, in chronological order.
    • Nothing is lost. The full run tag, the parameters and the file path are stored in the layer metadata (Layer Properties → Information).
    • Full file names restores the old behaviour: one group per output folder and the complete file name as layer name. Files whose names do not follow the DIC pattern are always loaded into a group named after the output folder.

    Layer opacity¶

    Transparency applied to every raster layer when loaded (default 80 %). Lower values let the basemap show through.

    Blending mode¶

    Next to the opacity: Normal (default) or Multiply. Multiply blends the loaded result rasters and coloured points with the layers below by multiplying the colours, so a hillshade or orthoimage underneath stays visible through the results without lowering their opacity. It is applied when layers are loaded; arrows are always drawn normally.

    Custom QML override¶

    Enable Override with custom QML for all layers and browse to a .qml file to apply a single style to every loaded layer, bypassing the per-component table.

    Global settings¶

    The Settings → Results section sets defaults applied on every scan:

    Setting Default Description
    Default range mode Auto Fixed or Auto for all components
    Percentile range 5 % – 95 % Low/high percentile bounds used in Auto mode
    Custom default ranges (table) Per-component Min/Max used in Fixed mode; Reset restores built-in defaults

    Range computation uses GDAL's histogram method — no full raster read is needed; overviews are used where available.

    Google Earth export¶

    Export selected layers as georeferenced KMZ overlays for Google Earth Pro. Supports time slider animation for multi-date datasets and an embedded colormap legend.

    Select one or more layers in the list and click 🌍 Export to Google Earth Pro… to create a georeferenced KMZ overlay and load it automatically in Google Earth Pro for a quick 3D visualisation with a legend indication.

    Option Description
    TimeSpan tags Adds KML <TimeSpan> tags so Google Earth Pro can animate layers using its time slider. Dates are extracted automatically from output subdirectory names (format YYYYMMDD). Requires at least two dates in the directory name.
    Embed colormap legend Inserts the colour bar as a screen overlay inside each KMZ, positioned in the bottom-left corner with component name, unit, and min/max values.

    Tip

    For a full time series, export all layers at once — each component gets its own KMZ plus a master KML that links them. Use the master KML in Google Earth to keep file sizes small and toggle layers independently.
